# refactor-v5 · ROADMAP（阶段交接文档）

> **面向**：任何接手 EmoWave 的 Agent / 开发者。先读这一份，再读各阶段记录。
> **最后更新**：2026-10-22
> **当前基线**：Phase 6 评估底座完成（`769 passed`，25,608 / 27,000 行）；7 天真实使用待开始。
> **总目标**：后端数据契约完善 + 前端 UI 重构，而不是“继续修后端”或“直接美化 UI”。

---

## 0. 一句话目标

> 后端负责让数据可信，接口负责让数据可用，UI 负责让数据易于理解。三件事形成闭环。

新阶段不是从零重做，也不是只做视觉。它要同时回答三个问题：

1. **数据是否可靠？** 记录、估计、时间推进、关闭重启后的恢复是否一致。
2. **接口是否足以支撑 UI？** UI 需要的数据能否通过清晰接口获得，而不是直接摸模型内部变量。
3. **UI 是否真正满足使用需求？** 信息层级、四类数据可区分、悬浮窗适合桌面快速查看、视觉统一。

## 4. 数据契约（当前有效）

### 4.1 `readouts_changed`

```python
readouts_changed = pyqtSignal(float, float, float, str, dict, float, float)
#                                  v      a     conf   ci   params  state_ts  last_obs_ts
```

- `state_ts`：这个读数是**几点**的模型估计；衰减/刷新路径上等于 `now`。
- `last_obs_ts`：最后一次**真实自评**的时刻；不是预测，也不是心跳。
- `v/a/conf/ci`：`latest_state` 的效价、唤醒、置信度、±1σ 区间。

### 4.2 `curve_changed`

```python
{
  "ts": [...], "mv": [...], "ma": [...], "vv": [...], "va": [...],
  "baseline_v": float,
  "raw": [(ts, valence), ...],
  "predicted_from": float | None,   # 该时刻之后是预测段（虚线）
  "corrections": [{"ts", "channel", "value"}, ...],
}
```

### 4.3 其他公共接口

| 接口 | 返回 | 语义 |
|---|---|---|
| `correction_context()` | `{has_data, timestamps, model_v, model_a, baseline_v, current_state}` | 纠正框所需的全部数据 |
| `current_mode()` | `idle / recording / decaying` | 生命周期 |
| `current_count()` | int | 本波自评数 |
| `curve_payload(start, end, resolution)` | dict / None | 统一曲线查询（带缓存） |
| `has_estimator_state()`（Phase 5 新增） | bool | 模型是否已有状态（供视图初始化判断） |
| `readout_payload()`（Phase 5 新增） | 7 元组 | 视图主动取一份读数 |
| `sync_snapshot()`（Phase 5 新增） | dict | 晚挂载视图的初始同步包 |

### 4.4 预测日志（Phase 6）

- 新表 `forecast_log`（不塞进 `app_state`，因为需要按 base/target 查询与聚合）。
- 每次记录预测时写入：`base_ts, target_ts, horizon_sec, valence, arousal, var_valence, var_arousal, source, created_at`。
- 评估时只使用**因果预测**（`predict_forward`），不使用 RTS 平滑曲线。

## 6. 设计原则

### 6.1 视觉

- 文艺、克制、简约；暖纸底 + 单一陶土色相；靠明度与留白分层，不靠重描边。
- 骨架保留构成主义的**大块面 / 不对称 / 几何**；容器与交互控件改为**柔和圆角**。
- 圆角只用令牌：`METRICS['radius']`（卡片/面板）、`radius_sm`（按钮/输入框）、`radius_mini`（悬浮窗）。
- 数字、时间戳、正文优先可读；字号层级不随页面变化。
- 动效轻量，不做弹跳；`EASE_OUT` 继续使用。

### 6.2 曲线语义（不可随页面变化）

| 元素 | 画法 | 含义 |
|---|---|---|
| 真实观察 | 实心小圆（弱） | 我说的 |
| 模型估计 | 实线 + ±1σ 带 | 模型算的 |
| 未来预测 | 虚线 | 猜的 |
| 用户修正 | 空心方框 | 我改的 |
| 基线 | 细虚线 | 我的正常值 |

### 6.3 交互

- 主窗首屏回答三问：现在什么状态 / 最近发生了什么 / 我能做什么。
- 悬浮窗是“桌面快速查看”，不是主窗缩小版；收起 ≠ 暂停。
- 空态必须给下一步；错误态必须说清“哪份数据、什么影响、怎么办”。
- 键盘：`Ctrl+R` 开始/停止记录，`Ctrl+N` 记一笔。
- 主窗与挂件消费同一份 payload，不各算一遍。

## 7. Phase 5 验收标准（✅ 已完成，证据见阶段文档 §4）

1. 全站圆角来自令牌，无硬编码 `border-radius: 0`（除有意保留的底部指示条）。
2. 400×680 与 360×600 下主窗无裁切；挂件收起/展开高度正确。
3. 空数据首屏显示可执行提示，不显示假曲线。
4. DB 打开失败 / 快照损坏 / 记录保存失败时，主窗有可见、可关闭的提示条。
5. 曲线悬停显示时间 + 值 + 语义（观察 / 估计 / 预测 / 修正）。
6. 视图不再直接访问 `presenter._*` / `presenter.estimator`（生产代码）。
7. 主窗与挂件数字逐字符一致（已有测试继续通过）。
8. 全量测试、架构护栏、无 GUI import、CLI、compileall、GUI 建窗全部通过。
9. README / 交接文档 / docs 索引同步到当前测试数与 v5 状态。

## 8. Phase 6 验收标准（评估底座 ✅；真实使用待完成）

1. `forecast_log` 表存在，记录因果预测，不把预测写成观察。✅
2. 日志有节流，不会每秒写库；重启后仍可读取。✅
3. 评估工具按 horizon 分组输出效价/唤醒的 MAE、RMSE、样本数。✅
4. 评估只使用预测时点可得的观察之后的数据，不使用未来信息。✅
5. 7 天使用清单与反馈模板就绪。✅（实际执行待用户积累数据）

## 9. 明确不在本阶段范围

- 重写 Matérn / Kalman / RTS。
- 更换 GUI 框架或引入 pyqtgraph / matplotlib。
- 6h / 24h / 7d 跨事件曲线（D4：暂缓）。
- 多用户、跨设备同步、安装包、崩溃上报。
- 大规模拆分 `ConsolePresenter`（只做接口收口，不做全面重写）。
- 用 RTS 平滑曲线证明预测准确（Phase 6 明确禁止）。
