## 2. UI—后端接口对照表

分类：**A** 已有可直接复用 / **B** 已有但需修复 / **C** 有基础需扩展 / **D** 缺失需新增

| # | UI 需求 | 现有接口 | 类 | 依据 |
|---|---|---|---|---|
| 1 | 当前效价与唤醒 | `readouts_changed(float,float,float,str,dict)` | **B** | `console_presenter.py:67`；值来自 `latest_state`，衰减期不更新（Phase 0 B） |
| 2 | 最近一次真实自评（值 + 时间） | 无 | **D** | 数据在 `observations[-1]` / `_last_obs_ts`，但无信号、无展示；`grep "上次\|分钟前"` 零命中 |
| 3 | 模型当前估计的**时间戳** | `latest_state.timestamp` 存在 | **D** | `readouts_changed` 签名不含时间戳，视图拿不到"这个数是什么时候的" |
| 4 | 个人基线 | `baseline_changed(float,float)` + `baseline_ctrl` | **A** | `console_presenter.py:75`、`main_console.py:443` |
| 5 | 当前与基线的**差值** | 无 | **D** | 需展示层组装（`latest_state - baseline`），两端都有数据但无派生 |
| 6 | 历史观察记录 | `db.get_events_by_date` / `get_all_event_dates` | **A** | `db.py:68,74`，`history_window.py:120` 在用 |
| 7 | 历史估计曲线（当前一波） | `curve_payload()` → `query_curve`（RTS） | **A** | `state_query.py:73`；含窗口与分辨率参数 |
| 8 | 跨事件历史曲线（24h/7d） | 无 | **D** | RTS 只吃内存 `observations`；事件表里只有 `raw_data` 摘要，没有重建入口 |
| 9 | 未来预测曲线 | `_tail_points` + `predicted_from` | **B** | `console_presenter.py:351`；恢复后整体平移（Phase 0 A） |
| 10 | 用户修正记录 | `_edits`（内存）+ `ingest_corrections` | **B** | `console_presenter.py:103,661`；**从不落库**，重启即失（见 §3） |
| 11 | 指定时间范围查询 | `query_curve(start,end,resolution)` | **C** | 接口有（`state_query.py:73`），**UI 无任何入口**：`grep "时间范围\|24 小时"` 零命中 |
| 12 | 状态更新时间 / 距上次自评 | 无 | **D** | 同上，无信号、无展示 |
| 13 | 数据缺失与错误状态 | `readouts_reset` / `curve_cleared` / 空数据文案 | **A** | `curve_widget.py` 空态文案；`main_console.py:439-441` |
| 14 | 重启后状态恢复 | `resume_active_wave` + `restore_recent_context` | **B** | `console_presenter.py:505,553`；Phase 0 A 的重复推进 |

**统计**：A 4 项 / B 4 项 / C 1 项 / D 5 项。

> 结论：**能支撑当前 UI，但支撑不了你规划中的 UI**。
> 缺的 5 项（D）集中在"时间语义可见化"——用户看不到"这个数是几点、离上次自评多久、比基线高多少"。
> 这正是 Phase 0 里"状态与曲线不同步"的用户侧表现。

## 3. 必须纠正的一处 v4 文档过度声明

v4 验收文档 `08-阶段7-验收.md` 第 7 项写：

> 曲线编辑 | **改点即重拟合、纠正持久** | `test_presenter_corrections_feed_calibrator` …

**"纠正持久"不成立。**

- `_edits` 在 `__init__` 里初始化为 `[]`（`console_presenter.py:103`），只在 `ingest_corrections` 里 `append`（`:694`），在 `_end_wave` 里清空（`:773`）；
- 全仓无任何代码把它写入 `app_state` 或事件表；
- `db.py` 只有三张表：`emotion_events` / `daily_summaries` / `app_state`，**没有 corrections 表**；
- 它引用的两个测试只断言"纠正喂给了 calibrator"，**没有任何持久化断言**。

后果：用户拖动曲线纠正历史点 → 重启后纠正消失 → 曲线回到纠正前。
这直接违反你 v4 方案 §5.1「纠正数据是否持久保存，并且能够用于后续校准」。

**处理**：Phase 2 补最小持久化（写 `app_state`，不建新表），并把 v4 文档那一行改成实情。

## 4. 三层边界审计

### 4.1 三层的实际落点

| 层 | 应有职责 | 现状 |
|---|---|---|
| 领域数据层 | 观察、纠正、基线、状态 | ✅ 干净：`emowave/core/domain/**`，零第三方依赖 |
| 展示数据层 | 组合好的展示语义 | ⚠️ **不存在**：payload 是散落的 dict / 5 元组，无类型、无契约 |
| UI 交互状态层 | 当前页、滑条值、窗口可见性 | ⚠️ 与展示层混在 `MainConsole` 里 |

### 4.2 越界清单（视图直接摸 presenter 内部）

`windows/main_console.py` 用 14 个转发属性把 presenter 私有成员暴露给视图：

```python

247  def estimator(self):     return self.presenter.estimator
251  def calibrator(self):    return self.presenter.calibrator
255  def baseline_ctrl(self): return self.presenter.baseline_ctrl

295  def _decay_now(self):    return self.presenter._decay_now        # 私有
```

另外三处直接调用私有方法：

| 位置 | 调用 | 问题 |
|---|---|---|
| `main_console.py:222` | `presenter.estimator.is_initialized` | 视图判断模型内部状态 |
| `main_console.py:576` | `presenter._readout_payload()` | 视图调私有方法取数 |
| `main_console.py:510-515` | 手工从 `states` 拼 `CorrectionSheet` 参数 | 视图自己做数据转换 |

**判定**：这不违反"不在 UI 里复制模型逻辑"（没有重算滤波），但违反"UI 不直接读模型内部变量"。
`_wave_active` 还带 setter——视图**能写** presenter 的状态，这是最危险的一处。

### 4.3 重复的展示转换

主窗 `_on_readouts` / `_on_curve_data` 与挂件 `_on_readouts` / `_on_curve` 各自把同一份 payload 拆成控件调用。逻辑相同、代码两份。
一旦展示语义变化（比如加"距上次自评"），必须改两处——这正是你担心的"两个窗口各自实现"。

## 5. 数据流图（以代码为准）

```
【用户动作】
  滑条 valueChanged
      └→ MainConsole._on_slider → presenter.submit_input(v|a)
            └→ ObservationRecorder.submit()          [防抖 350ms / 同值去重]
                  └→ committed 信号 → presenter._on_committed
                        └→ presenter.sample(v, a)
                              ├→ observations.append(Observation)     [领域]
                              ├→ estimator.update(obs)                [领域·滤波]
                              ├→ states.append((ts, EmotionState))
                              ├→ curve_payload() → RTSSmoother.smooth [领域·平滑]
                              │     └→ curve_changed(dict) → 主窗/挂件 set_data()
                              └→ readouts_changed(...) → 主窗 StateHead / 挂件读数

【时间流逝】
  QTimer(1s) ─┬→ recording? 否（v4 起不再造观察）
              └→ _wave_active? → decay_step()
                    ├→ horizon = now - _last_obs_ts
                    ├→ _tail_points(horizon)  ← 独立于 estimator 的第二套推进
                    │     └→ curve_changed(points=…, predicted_from=last_obs)
                    └→ latest_state  ← ❌ 不更新（Phase 0 问题 B）

  QTimer(300s, 仅挂件可见)
      └→ _on_refresh() → 若 recording 或 _wave_active 则 return
            └→ _refresh_now() → query_state() → estimator.advance_to(now)   ← ❌ 副作用
                  └→ latest_state 更新
```

**两条断点已标注**：`latest_state` 在衰减路径上不被写；`query_state` 在刷新路径上偷偷推进模型。

## 6. 接口契约草案（三个最关键接口）

### 6.1 `readouts_changed`

| 项 | 现状 | 应为 |
|---|---|---|
| 签名 | `(v: float, a: float, conf: float, ci: str, params: dict)` | 增加 `state_ts` 与 `last_obs_ts` |
| 时间语义 | 无 | 必须说明"这是 `state_ts` 时刻的估计" |
| 数据来源 | `latest_state` | 衰减期应等于曲线尾巴末点 |
| 可能缺失 | 未初始化时 `readouts_reset` | 保持 |

### 6.2 `curve_changed`

| 项 | 现状 | 应为 |
|---|---|---|
| 字段 | `ts, mv, ma, vv, va, baseline_v, raw, predicted_from` | 增加 `window`（start/end）与 `state_ts` |

| `vv/va` | 传了但视图不画 | Phase 3 决定画不画（不画就别传，别假装有） |

### 6.3 `StateQuery.query_state(target_ts)`

| 项 | 现状 | 问题 |
|---|---|---|
| 副作用 | **会** `advance_to`，永久改变 estimator 时间 | 名字与 docstring 都说"只读" |

| 建议 | 保留行为，**改名语义**：文档明确"推进式查询"；只读场景用 `estimator.current_state()` | Phase 2 只改文档与调用方，不拆类 |

## 8. 验收标准

### 后端数据接口"足够稳定"（可进入 UI 重构）

1. 衰减期 `latest_state.valence == 曲线尾巴末点 valence`（1e-9）；
2. 恢复后尾巴首点与历史末点差值 < 0.01（连续，无跳变）；
3. `readouts_changed` 带 `state_ts` 与 `last_obs_ts`；
4. 纠正重启后仍在，且参与后续 `learn()`；
5. 无同名重复定义（护栏守）；
6. 主窗与挂件不需要访问 presenter 的任何 `_` 开头成员。

### 主窗口重构完成

首屏能回答三问：现在什么状态 / 最近发生了什么 / 我能做什么；真实自评、模型估计、未来预测三者视觉可区分。

### 悬浮窗重构完成

隐藏≠暂停；"距上次自评"可见；与主窗读数在任意时刻一致（同一 payload，不是两次计算）。

### 整个 UI 阶段完成

空数据、加载失败、恢复失败都有明确提示；缩放不破版；主窗与挂件视觉同源（同一套 `theme.py` 令牌）。

## 9. 本阶段明确不做

- 不拆 `ConsolePresenter`（883 行）——但 Phase 3 起**禁止再往里加展示逻辑**，新逻辑进新对象；
- 不建新表、不改 schema；
- 不动 Matérn / Kalman / RTS；
- 不引入 pyqtgraph / matplotlib；
- 不做跨设备同步。
