## 1. 为什么挂件要单独设计

你方案 UI-2 里有一句关键判断：

> 悬浮窗应该单独设计，而不是把主窗口简单缩小。

Phase 1 审计发现挂件当时的问题：**它只是主窗的缩小版**——同样的双滑条、同样的记录按钮、同样的曲线，只是尺寸小一点。在 360×180 里塞这些，每样都不够用。

Phase 4 按"桌面快速查看"重新排优先级：

| 优先级 | 内容 | 处理 |
|---|---|---|
| 1 | 现在什么状态 | 头部状态名 + 三个大数字（始终可见） |
| 2 | 最近怎么变的 | 迷你曲线（始终可见） |
| 3 | 这个数可靠吗 | **距上次自评多久**（始终可见，新增） |
| 4 | 快速记一笔 | 记录 / ＋（始终可见） |
| 5 | 精细调整 | 双滑条（**收起时隐藏**） |

滑条是唯一被收起的部分——因为它最占高度，且只在"要精确输入"时才需要。

## 2. 收起 / 展开

```
收起（WIN_H − 46）          展开（WIN_H）
┌──────────────────────┐   ┌──────────────────────┐
│ 心潮 12 分钟前   紧张·焦虑 ↗ 钉 ▴ × │   │ 心潮 12 分钟前   紧张·焦虑 ↗ 钉 ▾ × │
│ 效价 62  唤醒 48  置信 71%  ● 开始 │   │ 效价 62  唤醒 48  置信 71%  ● 开始 │
│ ┌──── 迷你曲线 ────┐ │   │ ┌──── 迷你曲线 ────┐ │
│ └──────────────────┘ │   │ └──────────────────┘ │
└──────────────────────┘   │ 效价 ──●──  唤醒 ──●── │
                           └──────────────────────┘
```

**收起藏的是滑条那一条，不是整个交互。** 状态、曲线、记录按钮、记一笔全部保留——因为它们是"看一眼就知道"的信息。

### 三条行为规则

| 事件 | 行为 | 为什么 |
|---|---|---|
| 鼠标移入 | 展开 | 想操作时自然展开 |
| 鼠标移出 | 收起（**仅当未钉住**） | 不挡桌面 |
| 开始记录 | **强制展开** | 否则用户不知道能拖滑条 |

`set_expanded()` 只改 `detail` 的可见性与窗口高度，**不碰 presenter 任何状态**。

## 3. 钉住：默认开

`pinned` 默认 `True`。

理由：挂件的价值是"一直在那儿"。如果默认不钉，用户每次移开鼠标它就缩回去，反而要反复展开。

钉住 = 不自动收起。取消钉住后，移出即收起，但窗口仍在桌面上（不隐藏）——"收起"和"隐藏"是两件事。

> 与 v4 的 `setQuitOnLastWindowClosed(False)` 一致：**隐藏 ≠ 暂停**。
> 本阶段进一步明确：**收起 ≠ 暂停**。窗口形态与模型推进完全解耦，有测试守着（`test_mini_collapse_does_not_stop_refresh`）。

## 4. 距上次自评：挂件最容易骗人的地方

头部新增一个 8px 的灰字：`12 分钟前` / `刚刚`。

这一条在挂件上比在主窗上更重要。主窗有整条曲线和 meta 行，用户能看出"这是一段推演"；挂件只有三个数字，**如果不说，用户一定会把 0.62 当成"我现在 62"**，而它可能是两小时前自评、模型一路衰减推出来的。

数据来源：`readouts_changed` 的 `state_ts - last_obs_ts`（Phase 2 就备好了，本阶段只是显示）。

格式化复用 `windows/state_head._fmt_age`——**不复制第二份实现**。

---

## 5. 打开主窗：从右键菜单提到按钮

v4 只有右键菜单能回主窗，可发现性太差（没人会右键一个挂件）。现在头部有 `↗` 按钮，直接 `show_main_requested`。

右键菜单保留（显示主窗 / 退出程序）——退出仍只在菜单里，避免误触。

## 6. 双窗一致性：这次有测试了

Phase 1 审计时这条是"应该一致但没验证"。现在：

```python
def test_mini_and_main_show_same_numbers(qapp, tmp_path):
    ...
    assert win.mini.v_cell.value_label.text() == c.readout.v_lbl.value_label.text()
    assert win.mini.a_cell.value_label.text() == c.readout.a_lbl.value_label.text()
```

两个窗口连的是**同一组信号**，读的是**同一份 payload**，所以一致是结构保证的，不是巧合。这条测试守的是"以后别有人在挂件里另算一遍"。

## 8. 一处自我修正

写测试时我写了一条：

```python
assert mini.height() < win.mini.__class__ and True   # ← 拿高度和类对象比
```

跑起来是 `TypeError: '<' not supported between 'int' and 'sip.wrappertype'`。

改成与 `COLLAPSED_H` / `WIN_H` 常量比较。记在这里是因为：**这类断言如果写成 `and True`，很容易在别的地方悄悄通过**——它长得像断言，其实什么都没验。
