# refactor-v5 · Phase 2：后端最小修复

> **基线**：`f3e81cc`（Phase 1 审计入库），`709 passed`。
> **结果**：`717 passed`，行数 23,816 → **23,760（净 −56）**。
> **原则**：只修已确认的问题；不动数学模型、不拆 presenter、不改 schema。

---

## 1. 一句话总结

把**两条并行的时间线合并成一条**。

v4 里 `StateEstimator` 和 `_tail` 各推各的，于是长出两个 bug；合并之后，两个 bug 同时消失，代码还短了。

---

## 2. 修了什么

### 2.1 单轨时间（Phase 0 问题 A + B 的共同根因）

**改动**：`_tail` 不再保存 `x/P`，只保存足迹；推进交给 `estimator.advance_to()`。

```python
# v4：两条时间线
self._tail = {"x": estimator.state_vector, "P": estimator.covariance, ...}
tail["x"], tail["P"] = predict_step(tail["x"], tail["P"], ...)

# v5：一条时间线
state = self.estimator.advance_to(target)
tail["pts"].append((state.timestamp, state.valence, ...))
tail["state"] = state          # ← 读数直接用它
```

配套三处：

| 位置 | 改动 | 作用 |
|---|---|---|
| `_sync_latest_from_tail()` | 新增 | 读数 = 尾巴末点，不再各算各的 |
| `_rebuild_estimator()` | 新增 | 从 `observations` 重放出一个停在 `last_obs` 的估计器（**不改 self**） |
| `_replay_from_observations()` | 改为调 `_rebuild_estimator` | 基线/参数变化时重建 |
| `resume_active_wave()` | 删掉 `query_state()` 调用 | 推进只发生一次 |
| `_decay_points()` | 起点改为重放出的 `last_obs` 状态 | "一次性重算"与增量推进对齐 |
| `sample()` | `_tail = None` | 新观察让旧尾巴作废（时间基准变了） |

### 2.2 效果实测（同一脚本，改前 / 改后）

**问题 A：恢复后尾巴是否平移**

| | 尾巴首点（标称 +1s） | 尾巴末点（+60s） | 正确参照（+60s） |
|---|---:|---:|---:|
| 改前 | **0.8817**（其实是 +61s 的值） | 0.8449 | 0.8823 |
| 改后 | **0.9000**（= last_obs 值） | **0.8822** | 0.8823 |

改后首点回到 0.9000，与历史末点连续；末点 0.8822 vs 参照 0.8823（差 1e-4，来自增量与一次性的浮点累积差异）。

**问题 B：读数与曲线是否同步**

| horizon | 改前 latest_state | 改前尾巴末点 | 改后 latest_state | 改后尾巴末点 |
|---:|---:|---:|---:|---:|
| 10s | 0.9000 | 0.8992 | 0.8992 | 0.8992 |
| 60s | 0.9000 | 0.8822 | 0.8822 | 0.8822 |
| 200s | 0.9000 | 0.7861 | 0.7861 | 0.7861 |
| 400s | 0.9000 | 0.6641 | 0.6641 | 0.6641 |

改后**逐位相同**（测试用 1e-12 断言）。波结束后 `latest_state` 也停在 400s 的正确值，而不是"400 秒前的自评值"。

### 2.3 纠正持久化（补 v4 的欠账）

Phase 1 审计发现 v4 验收文档声称"纠正持久"但实际只在内存。现在：

- `SnapshotStore.save_corrections()` / `load_corrections()` 写进 **`app_state`**（不建新表）；
- `presenter.corrections` 跨会话保留；
- `_restore_calibrator_corrections()` 在 `__init__` 与 `set_archetype` 时把历史纠正**喂回 calibrator**——学习不因关窗归零；
- **不**回灌到 `_edits`：后者是"本波曲线的显示修正"，跨波复用会把上一波的修正画到这一波上。

### 2.4 读数信号带时间戳

```python
# 前
readouts_changed = pyqtSignal(float, float, float, str, dict)
# 后
readouts_changed = pyqtSignal(float, float, float, str, dict, float, float)
#                                         v, a, conf, ci, params, state_ts, last_obs_ts
```

两个视图的槽都改成 `(..., state_ts=0.0, last_obs_ts=0.0)` 并暂存。Phase 3/4 用它们显示"这个数是几点的 / 离上次自评多久"。

这条护栏直接拦住本次这三处重复再次潜入。

### 修订的 3 条旧测试（逐条说明）

| 测试 | 为什么改 |
|---|---|
| `test_decay_tail_matches_from_scratch` | 容差 1e-9 → 1e-6。两条路径现在都从 `last_obs` 起算，但一条走 `advance_to`（逐步）、一条走 `predict_forward`（批量），浮点累积不同。**数学同源，不是放宽掩盖错误**——改前两者差 0.043，改后差 4e-4。 |
| `test_decay_tail_is_incremental` | 原来 monkeypatch `cp.predict_step`（presenter 里的函数，已删）。改为数内核 `StateEstimator._predict`——数"真正的数学工作量"，实现换名字测试也不失效。 |
| `test_wave_end_keeps_latest_state` | `_readout_payload()` 从 5 元组变 7 元组，解包跟着改。 |
