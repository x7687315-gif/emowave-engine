## 0. 为什么要有这一阶段

数据接口正确、UI 显示正常，**不等于**情绪估计准确。要回答“模型准不准”，
必须在**观察发生之前**记录当时的预测，之后再用真实自评对照。

两条硬约束：

1. **不能用 RTS 平滑曲线反推“当时预测”**——RTS 是非因果的，用了未来信息；
2. **不能把预测当观察**——预测只写 `forecast_log`，绝不进入 `observations`、
   `emotion_events.raw_data` 或估计器。

因此本轮做的是：**因果预测日志 + 离线评估工具 + 使用清单**，不做模型参数调优。

## 1. 实现

### 1.1 新表 `forecast_log`

```sql
CREATE TABLE forecast_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    base_ts REAL NOT NULL,       -- 预测起点（模型当前时刻）
    target_ts REAL NOT NULL,     -- base_ts + horizon
    horizon_sec REAL NOT NULL,   -- 5m / 15m / 30m / 1h / 4h / 24h
    valence REAL NOT NULL,
    arousal REAL NOT NULL,
    var_valence REAL,
    var_arousal REAL,
    source TEXT,                 -- sample / decay / refresh / resume / restore
    created_at TEXT
);
```

- 建表用 `CREATE TABLE IF NOT EXISTS`，老库直接补表，不需要迁移脚本。
- 索引：`base_ts`、`target_ts`（评估时按目标时间找观察）。
- 不写入 `app_state`：预测是**时间序列**，需要按 base/target 查询与聚合，
  不是单个快照。

### 1.2 `presenters/forecast_logger.py`

| 项 | 规则 |
|---|---|
| 视界 | `300, 900, 1800, 3600, 14400, 86400` 秒（5m/15m/30m/1h/4h/24h） |
| 轨迹步长 | `min(300s, 最短视界)`；评估不需要秒级颗粒度，避免每次观察做 1440 步 |
| 触发 | 新观察 `force=True`；衰减 / 低频刷新按 60s 节流；恢复 / 重启恢复各留一份 |
| 计算 | `predict_forward`（因果状态转移；偏离空间回基线；方差随 horizon 增长） |
| 失败 | 只记日志，绝不打断记录/衰减；`db=None` 时 no-op |
| 去重 | 同一个 `base_ts` 只写一组 |

数据流：

```
sample / decay_step / refresh / resume
        └→ ForecastLogger.log(estimator, params, baseline)
              ├→ predict_forward（因果，无未来观测）
              ├→ db.save_forecasts(6 行/组)
              └→ 仅写 forecast_log（不写 observations）
```

### 1.3 评估工具 `python -m tools.forecast_eval`

```bash
python -m tools.forecast_eval --db ~/.emowave/emowave.db
python -m tools.forecast_eval --tolerance-min 15
```

做法：

1. 从 `emotion_events.raw_data` 与 `app_state.active_wave` 还原真实观察
   （当前没有独立 observations 表；这是 Phase 6 的已知限制）；
2. 从 `forecast_log` 读取因果预测；
3. 对每条预测，在 `target_ts ± tolerance`（默认 ±10 分钟）内找最近的观察；
4. 按 horizon 分组计算效价/唤醒的 **MAE、RMSE、样本数**；再给 overall。

示例（合成数据，验证 CLI 可运行）：

```
horizon      n      V MAE     V RMSE      A MAE     A RMSE
5m           1      0.100      0.100      0.100      0.100
1h           1      0.030      0.030      0.030      0.030
overall      2      0.065      0.074      0.065      0.074
```

> 这不是模型精度结论，只是工具自检。真实结论必须等 7 天使用数据。

## 2. 评估方法（必须遵守）

- **滚动起点 / 因果**：每条预测只使用 `base_ts` 当时可得的状态；不用 RTS；
- **按 horizon 分组**：短视界和 24h 视界的误差不可混在一起看；
- **观察匹配容差**：用户不一定恰好在 target 时刻自评，默认 ±10 分钟；
- **用户自评也有噪声**：指标衡量“模型与后续自评的吻合度”，
  不是对人类真实情绪的绝对测量精度；
- **样本量**：先积累 1–2 周；样本太少时只看方向，不下结论；
- **不要用“曲线好看”当准确**：曲线是平滑后的回顾，不是实时预测。

## 5. 7 天真实使用清单

> 目标不是“证明模型对”，而是收集**记录、恢复、曲线、交互**四类真实问题，
> 并为评估积累足够的“预测 → 后续观察”配对。

| 天 | 做什么 | 看什么 |
|---|---|---|
| 1 | 正常记录 3–5 次，每次 2–3 分钟 | 一次拖动是否只产生 1 条自评；有没有重复记录 |
| 2 | 记录后不关程序，去干别的 30 分钟 | 曲线按真实时间衰减；读数跟着曲线 |
| 3 | 记录后关掉整个程序，1 小时后再开 | 曲线是否过期消失；读数是否合理；有无快照损坏提示 |
| 4 | 打开悬浮窗、关主窗，用一整天 | 挂件 5 分钟刷新；收起不等于暂停；右键退出 |
| 5 | 拖动历史曲线纠正一个点 | 曲线即时重拟合；重启后纠正还在 |
| 6 | 回看历史页，补全事件 | 事件完整；导出可用 |
| 7 | 停止使用，运行评估工具 | 观察/预测条数；各 horizon 的 MAE/RMSE；记录异常 |

反馈请带：时间、操作、预期、实际、补充（是否休眠/导出 JSON）。
特别记录：重复自评、时间戳错乱、曲线跳变、恢复失败、主窗/挂件读数不一致。

评估命令：

```bash
python -m tools.forecast_eval --db %USERPROFILE%\.emowave\emowave.db --tolerance-min 10
```

解读规则：

- 先看每个 horizon 的 `n`；`n < 10` 的 horizon 不解读；
- 24h 的误差通常大于 5m，这是数学上的必然（方差随时间增长），不是 bug；
- 如果 5m/15m 的 MAE 明显大于 0.1（0–1 量表），优先查输入语义/时间戳，
  而不是换模型；
- 如果所有 horizon 都接近“预测一条平线”的误差，说明模型没有提供有效信息，
  再考虑回灌 24h/7d 或调整 ℓ。

## 6. 数据增长与维护

- 新观察：每组 6 行；一次 40 条自评的会话约 240 行；
- 衰减/刷新：最多 6 行/分钟；一天连续运行约 8,640 行；
- 预测日志开销：20 次 sample 平均 **14.1ms**（60s 步长时为 41.6ms）；
  日志只在新观察/衰减/刷新时写，不跟随 1Hz tick 强制写库；
- SQLite 完全能承受；若长期积累到数十万行，可在 Phase 7 加按时间归档/清理，
  但**不要**在没有评估结论前删除。
