## 1. 做了什么

### 1.1 静态层缓存：从"声称有"到"真的有"

Phase 0 审计 §3-F 记过：`_static_cache` 只被置 `None`，`_paint_static()` 每帧无条件重画，
所谓"网格/刻度缓存进 QPixmap"从未实现。

现在：

```
paintEvent:
    drawPixmap(0, 0, self._ensure_static(panels))   ← 网格/刻度/轴标签
    for each panel: self._paint_series(...)          ← 数据层（带/线/点）
```

缓存键 = `(宽, 高, 面板, 紧凑, t0, 时间跨度)`。

**关键：键里不含数据值。** 数据变了只重画数据层；只有尺寸或时间范围变了才重建静态层。
这正是"每秒刷新时不要重画网格"的正确形态。

HighDPI 也处理了：pixmap 按 `devicePixelRatioF()` 放大并 `setDevicePixelRatio`，
125%/150% 缩放下刻度不会糊。

### 1.2 预测段用虚线

以前"预测"只是把点追加到 `ts/mv` 尾部，视觉上和真实历史一模一样——
用户分不清哪些是测出来的、哪些是模型猜的。

现在 payload 带 `predicted_from`（= 最后一次自评的时刻），控件据此把曲线切成两段：

- `ts <= predicted_from` → **实线**（真实观察 + RTS 平滑）
- `ts > predicted_from` → **虚线**（外推），且与实线末点相连，不留断口

贯通路径：`presenter._emit_curve(points=…)` → `curve_changed` → 主窗/挂件 → `set_data(..., predicted_from=)`。
历史曲线（`query_curve`）显式返回 `predicted_from=None`。

## 2. 关于"每次刷新都重处理全部历史"

计划里这一条，现在可以给出**结论而不是优化**：

`_end_wave()` 会清空 `observations`，所以**一次记录（一波）内的观察数有上限**——
它等于"这一波里用户按了几次自评/拖了几次滑条"，而不是"记录了多少秒"。
Phase 0 实测的 126ms@N=600 需要 600 次自评才可能达到，而波在停止记录后
最多 600 秒就结束并清空。

所以：

- **不需要**为了性能引入增量 RTS 或节点网格平滑；
- 曲线缓存（Phase 2）解决"同一份数据算两遍"；
- 增量尾巴（Phase 3）解决"每秒重算整条尾巴"；
- 剩下的"每条新观察一次全量 RTS"在这个数据规模下是可接受的（N 通常 < 50，< 1ms）。

如果将来放开"跨波保留观察"（Phase 6 的 D4 备选），再回来做节点网格平滑。
