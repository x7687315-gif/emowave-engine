## 2. Phase 1 的范围（明确划线）

### 要做

1. **观察只由用户动作产生**：1Hz 心跳不再造 `Observation`。
2. **模型时间跟随墙钟**：`decay` / 刷新都基于 `time.time()`，不再累加 `DECAY_DT`。
3. **引入 `latest_state`**：波结束不清空"当前状态"，只结束动画。
4. **恢复读墙钟**：`resume` 用 `now - last_obs_ts` 计算真实 horizon。
5. **内核补一个公共入口** `StateEstimator.advance_to(timestamp)`：无观察也能推进到任意时刻。
6. **快照带版本号与时间语义**：`{schema_version, last_obs_ts, decay_started_at, samples}`。

### 不做（留给后续阶段，避免一次改太多）

- ❌ 5 分钟刷新调度（Phase 4）
- ❌ 主窗关闭后挂件独立存活（Phase 4）
- ❌ 全量 RTS 降频 / 增量（Phase 3）
- ❌ 曲线视觉（真实点/预测段区分、静态层缓存）（Phase 5）
- ❌ 数据库表结构变更（Phase 6，且只在证明确有必要时）
- ❌ 任何 UI 布局调整

## 3. 目标语义（Phase 1 完成后应成立）

```
真实观察 Observation
  └─ 只在三种时刻产生：① 用户停止拖动后（防抖 350ms）② 显式「记一笔」 ③ 用户纠正（伪观察，不落为 raw）
  └─ 每条都带真实时间戳与 source，append-only

状态估计 Estimate
  └─ latest_state = 模型对「现在」的估计
  └─ 可在无新观察时通过 advance_to(now) 推进
  └─ 波结束（动画消失）不改变 latest_state

预测 Forecast
  └─ predict_forward 的产物，只用于渲染，永不写入 observations / 不落库
```

**判据**：任意时刻 `len(observations)` 应等于「用户真实表达次数」，
而不是「记录秒数」。

### 4.2 内核（最小改动，1 个方法）

`emowave/core/estimator/estimator.py`

```python
def advance_to(self, timestamp: float) -> EmotionState:
    """无观测推进到指定时刻（预测步），返回该时刻的状态。

    与 update() 的区别：不产生、不消费 Observation，只推进模型时间。
    供「按需查询当前状态」使用（Phase 2 的 query_state 会复用它）。
    """
```

- 内部复用现有 `_predict(dt, control_arousal=0.0)`；`dt = timestamp - _last_timestamp`，沿用 600s 上限。
- **不改**数学、不改 `update()` 行为。
- 补 3 条测试（T4）。

### 4.3 新增 `ObservationRecorder`（新文件，~80 行）

`presenters/observation_recorder.py`

| 方法 | 职责 |
|---|---|
| `submit(valence=None, arousal=None, ts=None)` | 记录待提交值，重置防抖计时器 |
| `flush(ts)` | 到点提交：若有变化 → 产出 1 条 `Observation`；无变化 → 返回 None |
| `pending()` | 是否有未提交输入（供 UI 显示"待记录"） |

- 防抖用**一个可重启的 `QTimer`**（不用每次 `singleShot`，避免定时器堆积——检索台账 #2）。
- 只依赖 `QtCore.QTimer` + `emowave.Observation`，可脱离视图单测。
- 阈值常量 `DEBOUNCE_MS = 350`（你的方案 300–500ms 区间中值）。

### 4.4 `StateQuery`（新文件，~90 行）

`presenters/state_query.py`

```python
query_state(target_ts=None) -> EmotionState        # 默认 now
query_curve(start_ts, end_ts, resolution=None)     # 历史平滑 + 预测段
```

- Phase 1 只实现 `query_state`；`query_curve` 先透传到现有 `RTSSmoother`，
  **不做降频**（那是 Phase 3），避免一次改两件事。

### 4.5 `WaveScheduler`（新文件，~70 行）

- Phase 1 只做**时间源**：`now()` / `horizon_since(last_obs_ts)`，并持有可注入的 clock。
- 5 分钟周期刷新**留空**（Phase 4 加），避免 Phase 1 就引入后台调度。

> 拆三个对象的收益：presenter 从 541 行降到约 260 行，且每个对象可独立测试。
> 若你希望 Phase 1 只拆 `ObservationRecorder`、另两个留到 Phase 3/4，也可以——
> 见 §8 的可选方案。

### 4.6 `ConsolePresenter`（改，不改公开契约）

| 现状 | 改为 |
|---|---|
| `_on_tick()` → `sample(_input_v,_input_a)` | `_on_tick()` → **只推进显示/衰减**，不造观察 |
| `_decay_now += DECAY_DT` | `horizon = clock.now() - _last_obs_ts` |
| `_end_wave()` 清空 observations/states | 清空**动画态**（`states` 用于绘制可保留最近一段），保留 `latest_state` |
| `_store_active_wave()` `{end_ts,samples}` | `{schema_version:2, last_obs_ts, decay_started_at, samples}` |
| `resume_active_wave()` 不读墙钟 | `horizon = now - last_obs_ts`，一次性推进 |
| `sample()` 保留 | 语义改为"提交一条真实观察"，仅由 recorder / 纠正调用 |

**兼容**：`_decay_points(horizon)`、`current_curve_payload()`、`_readout_payload()` 签名不变
（`test_console_presenter.py` 与 `mini_window` 都在用）。

### 4.7 视图（只加最小接线，不改布局）

- `windows/main_console.py`：滑杆 `valueChanged` → `recorder.submit()`（替换当前的 `set_input` 直连）。
- `windows/mini_window.py`：同样走 recorder。
- **不加按钮、不改尺寸**。"记一笔"按钮留到 Phase 3 与 UI 一起做。

> 临时影响：Phase 1 后，用户"开始记录→不动滑块→停止"会得到 0 条观察。
> 这是语义正确的（用户没有表达新信息），但体验上像"没记上"。
> 因此 Phase 1 必须同时给出**可见反馈**：`count_changed` 文案从"N 个观察 · 1 Hz"
> 改为"N 次自评"，并在停止时若 0 条则提示"本次没有新的自评"。

## 6. 验收标准（Phase 1 专属）

| 项 | 判据 |
|---|---|
| 观察语义 | 记录 60s 不碰滑块 → 0 条新观察；拖一次滑块 → 恰好 1 条 |
| 时间语义 | fake clock 前进 1800s → horizon ≈ 1800s（误差 < 1s） |
| 不伪造 | 衰减 10 分钟后 `observations` 数量与开始时相同 |
| 状态常驻 | `_end_wave()` 后 `latest_state` 非空，挂件读数不为 "—" |
| 恢复 | 快照 30 分钟前 → 恢复后 horizon ≈ 1800s，且不重复插入观察 |
| 纠正 | 纠正后 `raw_data` 与原始 observations 未被改写 |
| 回归 | 全量测试通过；**允许**因语义修正而修改的旧测试必须在文档里逐条说明理由 |
| 性能 | `sample()` 在 N=600 时不再随秒级 tick 触发（记录期 CPU 显著下降） |

## 7. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 改 `_on_tick` 后旧测试红 | 逐条判断：断言"每秒采样"的测试是**旧语义**，改断言并记录；断言"生命周期"的保留 |
| 拆 3 个对象引入循环 import | `ObservationRecorder` 只依赖 `emowave` + `QtCore`；`StateQuery` 只依赖内核；presenter 依赖三者 |
| 用户数据（旧快照）解析失败 | v1→v2 兼容分支 + 失败时清空并记日志（现有行为） |
| 体验"记不上" | 文案改"N 次自评" + 停止时 0 条提示（§4.7） |

**回滚锚点**：实施前打 tag `v4-phase0`，每个子步骤一个 commit。
