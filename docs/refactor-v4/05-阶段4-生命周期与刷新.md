## 1. 做了什么

这一阶段解决的是"**关窗之后还算不算在跑**"——以前关主窗 = 进程退出，
所以"挂件常驻"从物理上就不成立。

### 1.1 应用生命周期

| 动作 | 以前 | 现在 |
|---|---|---|
| 关主窗（挂件可见） | 退出，挂件一起没了 | **只隐藏**，挂件继续跑，库保持打开 |
| 关主窗（挂件不可见） | 退出 | **退出**（停节律 → 关库 → quit） |
| 点挂件 ×（主窗还开着） | 只隐藏挂件 | 同左，不退出 |
| 点挂件 ×（主窗藏着） | 挂件没了，主窗藏着 → 僵尸 | **退出**（没有可见窗口了） |
| 退出程序 | 只能关窗口 | **挂件右键 → 退出程序**（显式入口） |
| 显示主窗 | — | **挂件右键 → 显示主窗** |

实现要点：

- `QApplication.setQuitOnLastWindowClosed(False)` —— 关掉"最后一个窗口自动退出"的默认行为；
- `MainWindow.closeEvent` 分两支：挂件可见 → `event.ignore()` + `hide()`；否则 `shutdown()`；
- `MainWindow.shutdown()` 幂等：停所有节律 → 关库 → 收挂件 → `app.quit()`；
- 挂件右键菜单提供「显示主窗 / 退出程序」，× 只隐藏（tooltip 已是"关闭挂件"）。

> **为什么要专门做退出入口**：一旦关窗不再退出，用户很容易以为程序关了、
> 其实还在后台跑。右键菜单是成本最低的显式出口，不引入托盘图标和新资源。

### 1.2 五分钟刷新

`presenter.refresh_timer`（QTimer，默认 300s）与 1Hz 心跳**是两条独立节律**：

| 定时器 | 服务什么 | 何时运行 |
|---|---|---|
| `timer`（1Hz） | 记录采样、衰减动画 | 记录中 / 衰减中 |
| `refresh_timer`（300s） | "没在记录时也想知道现在什么状态" | 挂件可见时 |

`_on_refresh()` 只做三件事：`advance_to(now)` → 更新读数 → 落盘 `latest_state`。
**不产生观察、不重拟合历史曲线**；记录/衰减期间直接跳过（1Hz 已在推进）。

挂件显隐与它绑定：`_toggle_mini` 打开 → `set_periodic_refresh(True)`，收起 → `False`。
普通查看模式（不挂件）不维持任何周期任务，符合"按需查看"。

### 1.3 一个必要的连带改动：`_end_wave` 不再重置 estimator

Phase 1 时 `_end_wave` 只是"不清理 latest_state"，但 estimator 仍被重建。
到了 Phase 4 就暴露了：**重建后 estimator 未初始化，低频刷新无从推进**，
挂件会永远显示波结束那一刻的快照。

所以改成：波结束只清 `states/observations`（动画数据），**estimator 保留**。
好处有两个：

1. 刷新能继续 `advance_to(now)`，状态随时间向基线收敛；
2. 下一次记录从当前估计继续，而不是每次从零开始——这才是"持续状态模型"。

真正的重置只发生在换人群（`set_archetype`）。

### 1.4 窗口显示时补时间差

`MainWindow.showEvent` → `presenter.refresh_now()`。
关掉再打开时，不必等 5 分钟，显示那一刻就把模型推到"现在"。
