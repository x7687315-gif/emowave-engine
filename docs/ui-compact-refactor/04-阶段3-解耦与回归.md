## 2. 怎么做的（4 个关键决策）

**① 反向输入用"显式参数"，不用"view 引用"**
presenter 不持有 view。要采样时由视图传值：`presenter.sample(v, a)`；而 1Hz 心跳由 presenter 自己按缓存的当前滑条值采样（`set_input(v, a)`，由视图滑杆 `valueChanged` 推动）。
→ 好处：**第二个视图（迷你置顶窗）可以复用同一个 presenter 而不抢状态**——这正是阶段 4 的前提，也是当初选"MVP 而非简单搬代码"的原因。守界测试：`test_presenter_has_no_qt_widgets_dependency` 用 **ast 解析真实 import**，断言 presenter 不 import `PyQt5.QtWidgets`（第一版用字符串匹配，误把 docstring 里提到的 QtWidgets 判成违规——已改 ast）。

**② v3 的公开属性一个没删，全改成 property 转发**
`observations / states / params / estimator / calibrator / baseline_ctrl / archetype / recording / _segment / _edits / _wave_active / _last_obs_ts / _decay_now / timer` 都是 `@property` 指向 presenter。
→ 30 条 v3 回归一行没改就全绿（包括读私有属性的 `c.calibrator._population.ell_arousal`、`c.curve.model_v`）。

**③ 删掉手写衰减，改调内核 `predict_forward`**
`_decay_points()` 曾手写 Matérn 衰减（`e^(-λΔt)(1+λΔt)`）。内核版是同一套数学，还多做两件正确的事：
- 在**偏差空间**传播（相对基线 `mean`，不是相对 0）——原注释说"estimator.extrapolate 是向 0 收，不适用"，指的就是这个坑；
- 每步叠过程噪声 Q → **外推越远方差越大**（"越预测越不确定"），而旧手写版方差恒定。

回归怎么证明真换了 API：`test_presenter_decay_uses_kernel_predict_forward` 断言 `max(var@120s) > max(var@5s)` —— 这个不等式只有内核路径能满足。

**④ 顺手修掉解耦暴露的两个 v3 隐患**
- **`estimator.baseline` 同步**：v3 的 `BaselineToolsCard._nudge/_fork/_reset` 里有一行 `self._est.baseline = self._ctrl.current`（把新基线同步进估计器）。解耦搬代码时这行极易丢——我第一版就丢了，`test_baseline_nudge_fork_and_reset` 立刻红。现在同步责任归 presenter（`_sync_estimator_baseline()`），并新增 `baseline_changed` 信号让基线卡刷新显示。
- **卡片持有失效引用**：`set_archetype()` 会 replace 新的 estimator/calibrator，而两个卡片在构造时抓住了旧对象引用。现在视图在换人群后调 `baseline_card.set_estimator()` + `refresh()`。
