## 1. 安全必修

### 1.1 `privacy_export` 伪加密 → 真 AES-256-GCM（P0，可被实证攻破）

**问题（安全审查实证）**：`_simple_encrypt` 实为「单次 SHA-256 派生 + 循环 XOR + base64」，但 README / 技术白皮书 / 模块 docstring 都宣称「AES-256-GCM」。安全代理**仅用代码固定的 JSON 前缀 + 文件名里可见的 8 字符 tag + 1 个暴力枚举字符**恢复密钥，完整解密了库里的 11.6KB 导出样本。这是「对用户的安全承诺造假」——用户以为导出的心理健康数据被加密，泄露后却谁都能解开。

**修法**：
- `_derive_key()`：`PBKDF2HMAC(SHA256, 600k 迭代)`（OWASP 2023 建议值），替代单次 SHA-256。
- `_simple_encrypt`：`AESGCM(key).encrypt(nonce, plaintext, None)`，16 字节随机 salt + 12 字节随机 nonce，输出格式升到 `EMW2`。
- `_simple_decrypt`：按前缀分流。`EMW2` 走 GCM；`EMW1` 保留**只读**兼容并 `warnings.warn`（明确告知该格式等于未加密、建议重新导出）；错误路径刻意不区分「密码错」与「被篡改」，避免给攻击者反馈。
- docstring / 模块头：「AES-256-GCM 风格或 XOR」的误导措辞改成「真 AES-256-GCM + PBKDF2（EMW2）；EMW1 历史 XOR 已实证可破，仅只读兼容」。
- `requirements.txt` 加 `cryptography>=42`（注释说明：属根目录导出器，不破坏 `emowave/` 内核零依赖）。

**新增回归测试** `tests/test_privacy_export_crypto.py`（6 条，锁安全属性而非实现）：往返 / 错密码被拒 / 篡改 1 字节被 GCM 认证标签发现 / EMW1 可读且发 UserWarning / 未知前缀拒绝 / 格式为 EMW2。

### 1.2 数据→UI 注入面收口

`event_summary_window` 等处把用户/DB 文本直接 `QLabel.setText()`，依赖 Qt AutoText 的富文本解析。当前数据源是固定复选框常量（不可利用），但一旦接入自由文本就是注入面。→ 统一 `setTextFormat(Qt.PlainText)` 关掉 HTML 解析，显示不变、风险归零。（详见下阶段批处理）

## 2. 我引入/半途而废的回归（逐条实证复现后修复）

MVP 解耦（阶段 3）与双视图拆分（阶段 4）时，有些 v3 行为漏搬了。正确性审查代理逐条写了复现脚本并实测，全部确认后才动手：

### 2.1 基线卡换人群后失效且污染活状态【中高】
`BaselineToolsCard` 构造时抓住 `baseline_ctrl` / `estimator` 对象，而 `set_archetype` 会 **replace** 新对象。阶段 5 我补了 `set_estimator`（半修），卡片仍写给已退役的 controller：实测换 low 后 label 显示 0.58 而 presenter 实际 0.50，点「+」后 `estimator.baseline=0.60` 与曲线基线 0.50 分叉，且再也修不回来。
**修**：卡片改纯视图——`baseline_provider` 每次拉当前 controller + `on_nudge/on_fork/on_reset` 回调走 presenter（顺带拿回 provenance 与 `baseline_changed` 信号）。`set_archetype` 不再手动换引用。

### 2.2 卡片按钮绕开 presenter，`_nudge/_fork/_reset` 成死码【中】
卡片四个按钮直连自己的 `_nudge`（改内核），而视图层的转发方法只有测试在调 → 测试守的是 UI 永不执行的路径。**修**：同 2.1，按钮一律走回调到 presenter。

### 2.3 停止记录后曲线不重拟合（漏搬 v3 的 `_refresh_curve`）【中】
v3 是 `_learn()` 后紧跟 `_refresh_curve()`；解耦时漏了，导致停止记录后曲线变成「旧 λ 的历史主体 + 新 λ 的外推尾」混在一条线上。实测 `presenter.learn()` 后 `curve.model_v` 不变。**修**：`learn()` 内重发曲线；`learn()` 改为先算到局部变量再一次性赋两处（避免中间失败留下混合参数）。

### 2.4 双视图输入互相覆盖【中】
主窗与挂件往同一 presenter 的 `_input_v/_input_a` 整体覆盖：实测「挂件调唤醒 0.9 → 主窗碰效价 → 唤醒被静默打回 0.4」。**修**：`set_input` 支持分通道更新（`valence=None` 表示不动该通道）+ `input_changed` 信号广播，各视图镜像对侧滑杆。

### 2.5 迷你窗晚于 `resume_active_wave` 接线，重启后状态错【中】
`MainConsole.__init__` 里调 `resume_active_wave()`，迷你窗那时还不存在 → 上一波未走完的衰减只通知主窗，挂件却显示「开始/可用」，用户会在挂件点「开始」打断正在进行的衰减。**修**：presenter 加 `current_mode/current_count/current_curve_payload` 快照接口，迷你窗接线时 `_sync_from_presenter()` 拉一次现状。

### 2.6 连按「开始」吃掉已采段落【低·v3 遗留】
守卫要求「不在记录中」，已在记录时再按会跳过收尾直接清空 `_segment`。**修**：入口加 `if want_running and self.recording: return`。

### 2.7 其他小修
- `ModelCard.refresh`：`getattr(p.stage,'value',…)` 会先求值 `p.stage`，provider 返回 None 时 AttributeError（`refresh()` 在 `__init__` 被调 → 「模型」页建不起来）。改为先取 `stage=getattr(p,'stage',None)`。
- `CorrectionSheet`：每次打开泄漏一棵控件树 → 加 `WA_DeleteOnClose`。
- 迷你窗曲线 `min_width` 从 `WIN_W` 派生（新增 `CURVE_GUTTER=20`），避免两处各写一份数字后被 `setFixedSize` 静默裁掉。
- 删除死信号 `wave_active_changed`（发射 4 处、两个视图都没订阅）。

## 3. 一致性必修：字体统一

一致性审查抓到我阶段 2 的一个**漏迁移**：`event_summary_window.py` / `history_window.py` 仍 `from widgets import app_font`，而 `widgets.app_font` 返回 Segoe UI，全站主题字体是 `theme.app_font`（Bahnschrift）。结果「历史」页两个活控件用 Segoe UI，其余全站 Bahnschrift——是活的视觉不一致。→ 统一切到 `theme.app_font`。
