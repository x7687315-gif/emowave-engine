## 2. 怎么做的（5 个关键点）

**① 挂件 = 第二个视图，零状态复制**
`MiniWindow(presenter)` 接收主窗的同一个 presenter，只多做两件事：接一套同样的信号、把自己的滑杆 `valueChanged` 转成 `presenter.set_input()`。
→ 这就是阶段 3 花一整段做解耦要换来的东西：**如果没有 presenter，就得把 estimator/timer/db 整套复制一份**，两个视图的状态会立刻分叉。测试 `test_mini_window_shares_presenter` 直接断言 `win.mini.presenter is win.console.presenter`。

**② 无边框置顶的标准配方**
`Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint | Qt.Tool`（`Tool` 让它不进任务栏）；
拖动由 `mousePress/Move/Release` 自己实现，用 `event.globalPos() - frameGeometry().topLeft()` 记偏移；
默认位置用 `primaryScreen().availableGeometry()` 的右下角（避开任务栏）。

**③ `self.mini` 必须由主窗口持有**
PyQt 里无父窗口的对象一旦失去 Python 引用就会被回收——表现为"点开图标闪退"。`MainWindow.__init__` 里 `self.mini = MiniWindow(...)` 常驻引用，`closeEvent` 里显式 `mini.close()`，否则主窗关了还会残留一个置顶小窗。

**④ compact 曲线 + `min_width` 参数（阶段 2 埋的伏笔在此用上）**
挂件里的曲线 `EmotionCurveWidget(series='valence', compact=True, min_width=WIN_W-24)`：compact 去掉图例与时间轴；`min_width` 是阶段 2 给 `curve_widget` 加的**参数化最小宽**——因为挂件只有 360px 宽，而控件默认最小宽 320 会把 Y 轴刻度（38px）挤爆。
高度 58–74px 用 `QSizePolicy.Fixed` 锁死，小窗不需要弹性曲线。

**⑤ 顺手修掉一个阶段 2/3 遗漏的真实 bug**
截图目检发现主窗状态名**从"低落 · 疲惫"被裁成"低"**：`row1` 里 `state_label` 没设最小宽度（QLabel 默认 `minimumSize` 为 0），空间不足时布局把它压成一个字的残字。
→ 修法不是写死像素，而是 `QFontMetrics(font).horizontalAdvance(最长状态名) + 4`——**DPI 无关**；同时把 hint 文案从"· 模型估计（不替你定义）"缩为"· 模型估计"并允许它优先让位（"不替你定义"这句产品承诺已存在于关于弹窗与参数说明卡里，不丢失）。
