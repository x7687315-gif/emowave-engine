### 2.1 架构地图（三代并存，两栈割裂）

**死代码**（可另行清理，与本次重构无关）：`windows/console_window.py`（零 import，连测试都没有）、`windows/dashboard_window.py`、`windows/surfing_window.py`、`onboarding.py`（全仓零 import）。

### 2.3 内核对 UI 的三个关键约束（来自 API 地图）

1. **Core 零 Qt 依赖、纯内存**，1Hz 节奏必须由 UI 层 QTimer 驱动；`update()` 对乱序时间戳抛 `ValueError`（**单调性由 presenter 单点保证**）。
2. **导入全是深路径**（`from emowave.core.estimator.estimator import StateEstimator`），包门面只导出数据模型 → presenter 里需要一个 `engine.py` 聚合层。
3. **`estimator.extrapolate()` 的衰减目标是 0 而不是 baseline**；回到基线的正确 API 是 `dynamics.predict_forward(mean=baseline)` / `predictor.forecast()`。
   → **`windows/main_console.py:722-744 _decay_points()` 是 UI 层手写的一份 Matérn 衰减**，应删除并改调内核 API，否则主曲线与迷你曲线会走两套数学。

## 3. 原方案复核：哪些对、哪些必须改

### 3.1 站得住的部分（保留）

| 原方案 | 复核结论 |
|---|---|
| 形态①：主窗 400×680 手机比例 + 形态②：迷你置顶窗 | ✅ 合理，且有现成配方（检索 #1/#7）。但迷你窗尺寸见 3.2-C |
| 顶部 Tab / 分段切换 | ✅ 合理。窄窗下比左侧图标列省宽 ~14%，且天然对应"手机底部 Tab 的未来" |
| 留 PyQt5 + 视图/逻辑解耦 | ✅ **最稳**。理由：a) Core 零 Qt 依赖使解耦成本低；b) 项目"Flet vs PyQt5"路线之争悬而未决，解耦后保留未来换栈自由 |
| 抽屉 → 整页（3 段拆成「模型」「历史」两个 Tab） | ✅ 合理；380px 并排在 400px 窗里物理上不可能 |
| 4 阶段划分（骨架→内容→解耦→迷你窗） | ✅ 合理，仅需在阶段 2/3 插入新发现项 |

### 3.2 必须修订的三处（硬伤）

**A. `main_app.py:23-25` 的 HighDPI 设置是空操作**

```python
Qt.AA_EnableHighDpiScaling = True      # ← 这只是给枚举对象加了个同名属性，Qt 根本不读
Qt.AA_UseHighDpiPixmaps = True
```

`ApplicationAttribute` 必须通过 `QApplication.setAttribute(...)` 在 `QCoreApplication` 构造**之前**设置（Qt 文档 + SO #10 五源一致）。当前状态下 125% 缩放下：**字号放大、但区块 setFixedHeight 是逻辑像素不变** → 按钮文字被裁（SO 67107900 实录）。

→ **修订**：改为在 `main()` 开头 `QApplication.setAttribute(Qt.AA_EnableHighDpiScaling, True)`；并**全面禁止 `setFixedHeight`**，改用 `setMinimumHeight` + sizePolicy（布局可长高），页头/Tab 这类需要稳定高度的也保留可扩展性。目标：125% / 150% 缩放下 400×680 内容不裁切、不出滚动条。

**B. 原高度预算漏算了 220px 的隐藏面板**

原预算：页头 44 + Tab 40 + 状态头 70 + 曲线 386 + 输入台 110 ≈ 680 ✅
真实情况：`StatusCard.params_panel` 展开时动画到 **220px**（`setMax/MinHeight(0↔220)`），一展开总高 ≈ 900 → 必溢出。且 `ReadoutBar` 固定 72px、曲线 `setMinimumHeight(280)` 都比预算大。

→ **修订后的高度预算 v2**（见下节 4.2）：状态头与读数条**合并成一条 56px**；参数说明折叠面板**移出小窗**，进「模型」Tab；曲线最小高度 **280 → 180**（`compact` 模式已是 96，控件本身 `Expanding` 无固定尺寸执念）。

**C. 迷你窗 280px 宽放不下曲线控件**

`curve_widget.EmotionCurveWidget.setMinimumSize(320, 96/180)` → 最小宽 **320px**。原计划迷你窗 280×160 **物理上摆不下**。

→ **修订**：迷你窗 **360×180**（并给 compact 模式把最小宽参数化，见 4.4）。

## 4. 修订版方案 v2

### 4.1 形态

- **主窗**：`setMinimumSize(360, 600)` + `resize(400, 680)`，单列布局，可拉大（拉大只增加曲线高度，**不做宽屏双栏**——这是"简化布局"的核心取舍）。
- **迷你置顶窗**：`360 × 180`，`Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint | Qt.Tool` + 拖拽 + `primaryScreen().availableGeometry()` 定位；与主窗**共用同一 presenter**（第二个视图）。页头新增图标唤起/隐藏。

### 4.2 纵向预算 v2（400×680，Win32 标题栏 ~30）
