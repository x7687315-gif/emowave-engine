## 2. 两个真 bug / 真问题的修法

**① `ModelCard` 显示旧值（v3 遗留，阶段 4 汇报中点名）**
卡片构造时抓住 `params` 对象，但 presenter 有两处会 replace 新对象：
- `set_archetype()` 换人群 → 新 params
- `Calibrator.learn()` 学习一步 → 返回新 params（version+1）
结果：**点"学习一步"数字不动、换人群后 ℓ 停在旧值**。
→ 修法：构造函数改为收 **provider（可调用）**，`refresh()` 每次从 `self.presenter.params` 拉；仍兼容传普通对象（`_get()` 兜底 `callable()` 判断）。视图侧在 `set_archetype` / `_learn` 后调 `refresh()`。
- 写测试时踩到的教训：`set_archetype()` 会**清空会话**（states=[]），所以测试里必须先重新采样再取 timestamp。

**② `test_recommender.py::test_serialization` 的 collection error（自项目开始就存在）**
根目录 `test_recommender.py` 是 1.x 脚本式测试，`test_serialization(bandit)` 缺 `bandit` fixture，pytest 每次都报一个 ERROR。全量跑时那个红字会**掩盖真实回归**（阶段 3 我就被一个 error 干扰过判断）。
→ 在仓库根新增最小 `conftest.py` 提供该 fixture。效果：全量从"673 passed, 1 error"变成 **"674 passed, 0 error"**。

**③ CI：仓库一直没有门禁**
新增 `.github/workflows/ci.yml`：
- 触发：push / pull request 到 `main`
- 环境：`windows-latest` + Python 3.9（与 `run_emowave.bat` 实际运行环境一致；3.14 下 PyQt5 会崩，别用）
- 步骤：装 `requirements.txt` → `QT_QPA_PLATFORM=offscreen` 跑全量 pytest → 无 GUI 导入冒烟（`main_app / presenters.console_presenter / windows.mini_window`）
- 已本地等价验证：offscreen 全量 674 passed、导入冒烟 OK、依赖清单齐全（PyQt5 5.15.11 / numpy 2.0.2 / pytest）
