## 2. 怎么做的（5 个关键决策）

**① 状态头合并 = 纵向预算能平账的关键**
v3 状态卡（含 220px 折叠面板）+ 读数条合计约 160px。合并后一条 ~68px：

```
┌───────────────────────────────────────────────┐
│ 平静 · 偏积极   · 模型估计（不替你定义）  [· 情绪有误] │
│ 效价 55   唤醒 42    置信 99%   区间 48 – 50          │
└───────────────────────────────────────────────┘
```

多出的 90px 全部还给曲线（220 → 340）。**v3 的属性名一个没丢**（`state_label/state_hint/corr_btn/v_lbl/a_lbl/c_lbl/ci_lbl` 都还在，`v_lbl` 等仍是带 `.value_label` 的容器），`console.readout` 作为**指向同一对象的兼容别名**保留——这样 `test_legacy_panels_*` 等 30 条 v3 回归里凡是读到 `console.readout.xxx` 的一行都没改。

**② 220px 参数说明面板移进「模型」Tab，并去掉折叠动画**
小窗放不下 220px 的展开面板，但模型页整页有空间 → 改成**常驻展示**（`ParamsExplainCard`），`PropertyAnimation` 折叠动画与"是否展开"状态一并删除。**少一套动画 = 少一类 bug**，且参数说明和「个人模型」的模型参数放在一起语义更顺。

**③ 纠正框改上下布局，但 `applied` 契约一字未动**
900×520 左右 2:1 在 400px 宽下物理不可能。改成 400×480 上下：上双曲线、下「时刻/效价/唤醒」一行三格（复用 `_field()` 小工厂：极小标签在上控件在下）。
→ `self.applied = [(ts, v, a), …]`、`_on_select` / `_on_drag` / `_on_manual_edit` / `_apply` 全部原样，`MainConsole.ingest_corrections()` 一行没改。

**④ 拖点命中容差从 6px 改成 `max(4, ph*0.12)`**
硬编码 6px 在大面板占比小、无感；小窗里双曲线每个子图只剩约 90px，6px 变成"中间空白区也能拖"，手感直接坏掉。改成按子图高度取比例后，缩放无关。

**⑤ 冷色板统一 = 改 widgets.py 一处，而不是改两个遗留窗口**
`event_summary_window` / `history_window`（经 LegacyEmbed 进「历史」Tab）import 的是 `widgets.COLORS`，若逐个文件换 import 要动两处且键名还得核对。直接让 `widgets.COLORS` **就是** `theme.COLORS`（旧冷色板降级 `COLORS_COLD`），一处改动全统一；顺带把 `CardFrame` 的 `border-radius: 6px` 改成 0——那也是违反"全站圆角 0"构成主义 token 的历史残留。
（用前已核对：两个遗留窗口用到的 8 个键在 `theme.COLORS` 里全都有。）

## 4. 过程中修掉的一个小窗挤压

阶段 1 遗留的输入台文字截断（"55 个观"被右侧裁掉）：根因是 `count_label` 与 `tip_label` **两个标签**在 400px 里抢宽度。→ 合并成一个标签 `"55 个观察 · 1 Hz"`，并删掉 `tip_label`（原提示语"拖动滑块即时采样，1 Hz 喂给模型估计器"在 400px 下不可能完整显示）。
