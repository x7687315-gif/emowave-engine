## 2. 怎么做的（3 个关键决策）

**① 抽屉 → 三页，而不是"抽屉变窄"**
380px 抽屉 > 400px 窗口，无法并排；改成 `QStackedWidget` 三页后，导航宽度与窗口宽度解耦（Tab 百分比均分）。次要页（模型/历史）用 `QScrollArea` 包住——保留 v3 抽屉时代"靠下内容必须能滚到"的约束，`test_secondary_pages_are_scrollable` 守这条。

**② `IconButton` 的 `drawer`/`curve` 图标删除，`set_active()` 语义改通用**
原 `set_active` 画"左边缘指示条"，是图标列专属；现在只剩 hover 强调（`_active` 字段保留但不再画条），当前页高亮交给 Tab 栏的**底部 2px accent 条**（QSS `#TabBtn:checked`）——同一构成主义语汇，不再需要每个按钮自己画。

**③ HighDPI：把空操作改成真设置**

```python
# v3（无效）：只是给枚举对象加了个同名属性，Qt 从不读取
Qt.AA_EnableHighDpiScaling = True

# v3.1：QApplication 静态方法，必须在 QCoreApplication 构造前调用
QApplication.setAttribute(Qt.AA_EnableHighDpiScaling, True)
```

阶段 1 同时把 `setFixedHeight` 全部改成 `setMinimumHeight` + sizePolicy —— 页头也从 `setFixedHeight` 改为最小高度 + 控件垂直居中，允许窗口被内容顶高（这消除了 125% 缩放下文字被裁的最大风险源）。

## 4. 过程中踩到并修掉的 2 个 bug（都写成了回归）

**Bug A：`page_model` 忘加进 `stack`**
`_build()` 只 `addWidget` 了曲线页和历史页，切到索引 2 被 Qt 静默忽略（停在 1）。被 `test_tabs_switch_pages` 抓到。
*教训*：`QStackedWidget.setCurrentIndex` 对越界索引不报错、直接 no-op —— 新增页必须显式 addWidget，且要用"实际可见性"断言，不能只看调用没抛异常。

**Bug B：`set_current()` 用 `checkedId()` 去重 → Tab 变死按钮**
可检查按钮的 `click()` 会**先把按钮翻成 checked 再发 `clicked`**，此时 `checkedId()` 已是新页索引，`set_current` 误判"没有变化"提前 return → 信号不发、页面不切。被 `test_tab_click_actually_switches_page` 抓到。
*教训*：这与 v3 当年"曲线按钮没接 clicked"是**同一类回归**（用户点了但界面没反应），所以改用自维护的 `self._current` 做去重，`click()` 导致的按钮态漂移只在"点当前页"时补正。
→ 这也解释了为什么那 3 条测试值得写成"实际页面切换"而不是"标志位翻转"。

## 6. 环境坑：offscreen 平台在本机**不渲染字体**

阶段 1 截图一度"全是空白、只有图标"，排查后确认**不是代码问题**：

- A/B 实验（同一份代码，只切 `QT_QPA_PLATFORM`）：`offscreen` 下 **QLabel / QPushButton 的文字全部不绘制**（QPainter 手绘图标与 QSS 边框正常）；换回默认 **windows** 平台插件后文字完全正常。
- `tests/conftest.py` 设 `QT_QPA_PLATFORM=offscreen` 只是为了无头跑断言（对象属性，不碰像素），不受影响。
- 但 `docs/shot_app.py` 的 docstring 本来就写着"必须用 Python 3.9：该环境 PyQt5 5.15.2 带 windows 平台插件"——截图必须用 windows 平台。

→ **规则固化**：以后凡是"截图/目检"一律不加 `QT_QPA_PLATFORM=offscreen`；凡是"跑测试"才加。本次 4 张截图（01-main / 02-model / 03-history / 04-correct-sheet）已用正确平台重拍。
