## 3. 删除决策：按纪律，需要用户点头（绝对不可逆的一类）

`absolute-prune` / `repo-cleanup` 的共同红线：**不可逆删除（大批量源码）必须先过 Gate，用户批准后才动**。前面 Wave 1 只删「可再生 / 已忽略 / 死环境」，零代码风险；Wave 2 的 12.5k 行死代码删除则不同：

- **风险**：一旦删错引用点，虽然 `git revert` 可回滚，但会让「研究/评估历史」不可复现（这些脚本产出了 `benchmark_results/`、白皮书等留档）。
- **决策点（请选其一）**：
  1. **全删**（最激进）：连同 `test_data/`、`benchmark_results/` 等生成物一起清，仓库最瘦，但研究历史不可复现。
  2. **归档后删**（推荐）：把 `1.x` 死簇 + 其生成物移入 `archive/legacy_1x/`（保留在库、可复现、不参与 CI），主目录与打包彻底干净。
  3. **暂不动**：只做 Wave1（磁盘）+ Wave3（路径/文档），代码尾巴留待你后续拍板。

无论选哪个，都会作为**独立 commit**，你可用单条 `git revert` 撤销。
