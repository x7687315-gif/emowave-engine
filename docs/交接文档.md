## 1. 现在能不能进入"实地测试 → 反馈 → 优化"？

**能。但先把下面四件事做了。**

### 1.1 测试前必做

1. **备份数据库**（唯一不可再生的资产）：
   ```
   复制 %USERPROFILE%\.emowave\emowave.db  到别处
   ```
   v4 没有改表结构，v3 的库可以直接用；但语义变了，出问题要能回退。
2. **确认解释器**：必须是系统 Python 3.9（带 PyQt5）。托管版 3.13 没有 PyQt5。
3. **跑一遍测试**（30 秒）：`python -m pytest -q`，应为 **769 passed**。
4. **记住回滚锚点**：tag `v4-phase0`（v4 开工前）与 `archive-v1-legacy-2026-10`（大瘦身前）。

### 1.2 这一轮到底改了什么（用一句话说清）

> 以前是「打开窗口就每秒记录一次」，现在是「你说一次，它记一次；
> 你没说，它只按真实时间推演」。

### 1.3 已知限制（测试时会遇到的）

| 限制 | 表现 | 是否阻塞测试 |
|---|---|---|
| 没有安装包 | 只能 `run_emowave.bat` 从源码跑 | 否 |
| 只在 Windows 验证过 | macOS/Linux 未测 | 否 |
| 模型精度未验证 | 曲线可能"看着顺"但预测不准 | 否，但这正是要收集的反馈 |
| 挂件必须可见才低频刷新 | 挂件收起后，只有打开主窗才更新"现在" | 否 |
| 7 天前的数据不参与恢复 | 长期不用后打开，显示的是上次落盘的状态快照 | 否 |
| 观察没有独立表 | 只存在事件的 `raw_data` 里；导出只有事件 JSON | 否，但影响后续分析 |

### 1.4 建议的反馈格式（重要）

每条反馈请带上这五项，否则很难定位：

```
时间：2026-10-20 14:03
操作：开始记录 → 拖效价到 30 → 记一笔 → 停止 → 关主窗（挂件留着）→ 30 分钟后回来
预期：曲线在 30 分钟后应接近基线，挂件读数有变化
实际：曲线消失了，挂件还显示 30 分钟前的值
补充：期间电脑休眠过一次；导出的 JSON 见附件
```

**特别值得盯的五个点**：

1. 一次拖动是否只产生 **1 条**自评（不是几十条）；
2. 电脑休眠/长时间不用后，曲线的时间轴是否"跳得合理"；
3. 情绪波是否该消失时消失、不该消失时提前消失；
4. 主窗与挂件的读数是否**始终一致**；
5. 关主窗/关挂件后，程序是否**真的退出**（任务管理器看进程）。

## 2. 项目现在是什么样

### 2.1 技术栈

| 层 | 技术 | 约束 |
|---|---|---|
| 内核 `emowave/` | 纯 Python 标准库 | **零第三方依赖**（架构护栏强制） |
| 桌面端 | PyQt5 5.15.11 + QPainter 自绘 | 唯一运行时依赖 |
| 存储 | 本地 SQLite（`~/.emowave/emowave.db`） | 不上传任何数据 |
| 测试 | pytest + pytest-qt（offscreen） | 769 条 |

### 2.2 目录（只看这些就够）

```
emowave/                内核（pip 可安装，零依赖）
  core/estimator/       Kalman（Matérn ν=3/2）—— L1 感知层
  core/curve/           RTS 平滑 + 可编辑曲线 —— L2 回顾层
  core/calibration/     个人校准 + 基线主权 —— L3/L4
  core/inference/       predict_forward / predict_step / TrendPredictor
  adapters/             storage（SQLite 适配器）· agent（Amiya 桥）

presenters/             编排层（不 import QtWidgets，可无 GUI 单测）
  console_presenter.py  唯一持有内核对象的地方（最大的文件）
  observation_recorder.py  什么算一次自评（防抖 350ms）
  state_query.py        某时刻状态 / 某段曲线（带缓存）
  wave_scheduler.py     全应用唯一时间源
  snapshot_store.py     active_wave / latest_state 的读写与校验
  forecast_logger.py    因果预测快照（forecast_log，评估用）

windows/                视图（只接信号、只传参数）
  main_console.py       三页主界面（曲线/模型/历史）
  mini_window.py        360×180 置顶挂件（右键菜单：显示主窗/退出）
  notice_bar.py         主窗可关闭的降级/错误提示条
curve_widget.py         曲线控件（静态层缓存 + 预测段虚线 + 悬停读数）
main_app.py             外壳 + 生命周期（关窗≠退出）
db.py                   应用层 SQLite（事件 / 日摘要 / app_state / forecast_log）
tools/forecast_eval.py  离线评估：按 horizon 输出 MAE/RMSE
```

## 3. 我们首先做了什么事

整个项目经历了两件性质完全不同的事，别混在一起看。

### 3.1 第一件事：把"尾巴"砍掉（2026-10-17）

**问题**：仓库 41k 行，其中 45% 对出货路径零引用——两次架构迁移都没收尾，
1.x 引擎栈、研究脚手架、一次性脚本全留在根目录，互相 import 续命。

**做法**：用 AST 可达图取证（入口只取 `main_app` + `emowave.cli`），
分四波删除，每一波都跑全量测试：

| 波次 | 内容 | 结果 |
|---|---|---|
| A | 研究/评估死簇（模拟器、基准、评估、白皮书、性能剖析…） | −9,883 行 |
| B | 1.x 引擎栈 + 从未接线的模块 + 死窗口 | −9,509 行 |
| C | 架构护栏（防尾巴再生） | +182 行 |
| D | 文档收敛（根目录 8 份 MD → 只剩 README） | −997 行 |

**结果**：41,086 → 21,883 行（−46.7%），仓库 22MB → 7.9MB，依赖只剩 PyQt5。

### 3.2 第二件事：把"时间"理清（2026-10-19，v4）

**问题**：不是代码多，而是**语义错**：

- 记录期间每秒把滑条值复制成一条"观察"（10 次心跳 = 10 条同值记录）；
- 模型时间 = 定时器触发次数 × 1 秒（真实过 1.2s，模型只走 1.0s）；
- 波结束就清空观察 + 重建估计器（模型不是持续的，是"一次性动画"）；
- 预测点和真实历史画得一模一样（用户分不清哪些是猜的）。

**做法**：8 个阶段（Phase 0–7），每阶段先写测试、再改实现、独立 commit、跑 15 轮验证。

**结果**：语义正确了，代价是 +1,933 行（其中约 1,150 是测试）。

### 4.1 计划外的两个真 bug（值得单独记）

**① 估计器的预测步在把状态拉向 0，而不是基线。**
`_predict()` 直接 `x ← F·x`，而 Matérn 的 F 把均值回复到 0；曲线尾巴走的
`predict_forward()` 却在偏离空间里做（回到基线）。1Hz 连续采样时看不出来，
一旦"按真实时间外推"成为主路径就暴露了。修法：`_predict` 也改成偏离空间传播。

**② `update()` 把 1 小时的空档当成 10 分钟。**
`dt = min(dt, 600)` 是为了防发散，但它把时间"吞掉"了。修法：按 600s 分段推进，
总推进量 = 真实间隔。

### 4.2 为什么每阶段都要跑"15 轮验证"

单跑一次 `pytest` 不够：GUI 相关的 bug（生命周期、绘制）在普通断言里抓不到。
所以固定跑 15 轮：全量 / 内核 / 桌面 / 护栏 / 无 GUI import / CLI 四命令 /
compileall / 内核依赖探针 / GUI 建窗 / 稳定性 ×3。

## 5. 五条关键不变量（接手必须知道）

1. **`emowave/core/**` 零第三方依赖。** 有护栏测试，加了 numpy 会红。
2. **视图不 import 内核类。** 视图只接信号、只调 presenter 方法。
3. **观察 append-only。** 纠正（`UserCorrection`）是**额外的伪观察**，不覆盖原始数据。
4. **预测永远不落库、不变成观察。** 有测试专门守这条。
5. **时间只有一个来源：`WaveScheduler.now()`。** 任何地方再写 `time.time()` 都算 bug。

## 6. 现在遗留的问题

### 6.1 功能/语义层（P0–P1）

| ID | 问题 | 影响 | 建议 |
|---|---|---|---|
| **P0-1** | 没有留出评估集，**模型精度未知** | 不知道"准不准"，只能看手感 | 用真实使用数据做 MAE/RMSE |
| **P1-1** | 历史观察只回灌"最近一条事件" | 长期不用后，模型上下文很薄 | 等评估结果再决定是否回灌 24h/7d |
| **P1-2** | `console_presenter.py` 已 883 行 | 再加功能会继续膨胀 | 下一轮把"曲线组装/持久化编排"再拆出去 |
| **P1-3** | 观察没有独立表 | 无法做跨事件的统计分析 | 若要评估，先加 `observations` 表或从 `raw_data` 抽取 |
| **P2-1** | 挂件收起后不刷新"现在" | 主窗也关着时，状态会停在收起那一刻 | 可接受；如需常驻，改挂件可见性策略 |

### 6.2 工程层（P2）

- **无安装包**：只能源码运行；`run_emowave.bat` 写死了 Python 3.9 路径。
- **无崩溃上报**：出问题只能靠用户描述 + 导出 JSON。
- **导出只有事件**：不含观察明细、不含模型参数、不含基线历史。
- **单机单用户**：没有多用户隔离，也没有跨设备同步（设计如此，但要知道）。
- **测试依赖 offscreen**：真实显示器下的 HighDPI/多屏行为未覆盖。

### 6.3 明确"没做"的三件事（避免误以为做了）

1. 没证明模型更准（只证明了语义正确）；
2. 没做 24h/7d 历史回灌；
3. 没优化"每条新观察全量 RTS"（因为 `_end_wave` 会清空观察，N 不可达 600）。

## 10. 术语表

| 术语 | 含义 |
|---|---|
| **观察 Observation** | 用户**真实表达**过一次感受（拖滑条/记一笔/纠正） |
| **估计 Estimate** | 模型结合观察算出来的状态（`latest_state`） |
| **预测 Forecast** | 没有新观察时向未来的外推（曲线虚线部分） |
| **波 Wave** | 一次「开始记录→停止→衰减回基线」的动画周期 |
| **基线 Baseline** | 用户的"正常值"，情绪衰减的目标（不是 0） |
| **Tier T0/T1/T2** | 能力分档，低配设备可降级 L2/L3/L4，L1 永远保留 |
| **RTS** | Rauch-Tung-Striebel 平滑，非因果，用于"拖动一点整条曲线变形" |
| **Matérn ν=3/2** | 情绪曲线的核函数，ℓ 就是"情绪惯性"（可学习） |
