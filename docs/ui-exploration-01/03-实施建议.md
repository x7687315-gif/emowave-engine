## 2. 必改项（与选 A/B 无关，两套都要）

### 2.1 一行 QSS 角色修正（A 唯一的无障碍债，B 也受益）

`theme.py` 里 flat 按钮 hover 前景用了 `accent`：

```
QPushButton:hover { border-color: accent; color: accent; background: accent_soft; }
```

问题：`accent` 的定义职责是"图形与大号数字"（3:1 阈值），这里被拿去当**小号文字色**用。
生产实测 3.38:1，A 亮 4.06:1，都低于 4.5。改成 `accent_ink` 后：生产 4.16→、A 亮 **5.93:1**、B 亮达标。

> 这不是"金色不行"，是**令牌角色串位**。修完之后 A 亮 0 项不达标。

### 2.2 5 处 import 期颜色固化 → 运行期读取

| # | 位置 | 现状 | 改法 |
|---|---|---|---|
| 1 | `curve_widget.py:567` | `_WASH_RGBA = _parse_rgba(COLORS['wash'])` | 改成函数内 `global` 缓存 + `theme_version` 失效；或模块级 `def _wash(): return _parse_rgba(COLORS['wash'])` |
| 2 | `curve_widget.py:569` | `_RAW_RGBA = CURVE_STYLE['observation']['color']` | 同上 |
| 3-5 | `main_console.py:143/151/157` | `_BTN_*` 类属性 f-string | 改成 `@classmethod def _btn_qss(cls)`，或 `set_mode()` 里现算 |

**为什么必须改**：不改的话，"切换主题"要么不生效，要么必须重启进程。
原型现在就是靠"每主题一个子进程"绕过去的（见 `prototype.py` 顶部注释），
那是探索手法，不是产品能力。

### 2.3 已验证缺陷 D6：纠正框时刻裁字

`windows/correction_sheet.py` 里 `tm_lbl.setFixedWidth(78)`，
而选中态文案 `13:20:47` 在 `app_font_num(13, Light)` 下实测需 **104px**。
生产 v5 截图只拍过未选中态（`—`），所以一直没暴露。

改法照抄 Phase 5 在输入台用过的办法：
```python
num.setFixedWidth(QFontMetrics(num.font()).horizontalAdvance('13:20:47') + 8)
```
并补一条测试：**选中某个点后**断言时刻标签未被裁（`sizeHint().width() <= width()`）。

### 2.4 最后一处硬编码色

`windows/history_window.py:170` 的 `QColor('#DFE7D8')` → 换 `accent_soft`。
换完 `theme.COLORS` 就是全站唯一颜色来源（本轮扫描确认：除此之外零硬编码）。

## 3. 主题化需要新增的东西（若暗色进范围）

```
theme.py
  COLORS_LIGHT = {...}          # 现 COLORS
  COLORS_DARK  = {...}          # 新
  def apply_mode(mode)          # 原地 update COLORS + CURVE_STYLE['observation']
  def current_mode()
  # 曲线 observation 的 RGBA 也要随模式走（现在是元组常量）
```

要点：
1. **`CURVE_STYLE` 的 observation 色是元组不是令牌**，暗色下必须换值——
   本轮 `palette_tokens.OBSERVATION` 已经演示了正确形状（按模式给元组）。
2. **暗色三条校准规则**（`01` §3.2）：高度方向、`accent_deep` 反向、`accent_soft` 用暗 tint。
   机械反色会得到一个"能看见但全是债"的暗色主题。
3. 切换入口：页头加一个图标（`IconButton` 已有绘制范式），持久化写 `app_state` 键值表
   （表已存在，`db.py` 有 `get_state/set_state`，`archetype` 就是这么存的）。
4. 跟随系统：Qt5 无官方 API，需读注册表 `Themes\Personalize\AppsUseLightTheme`。
   **建议第一版不做自动跟随**，只做手动切换——少一个不可控变量。

## 4. 建议新增的护栏测试

| 测试 | 断言 | 防什么 |
|---|---|---|
| 对比度护栏 | 把 `contrast_report.CHECKS` 搬进 `tests/`，两套模式各跑一遍，任何一项 < 阈值即红 | 以后有人手调一个色值就悄悄掉出 AA |
| 中性轴色偏 | 8 个中性令牌平均 chroma ≤ 12（亮）/ ≤ 12（暗） | 防止"底又慢慢染色"——本轮 B 暗色 18.8 就是这条要拦的 |
| 强调色饱和度 | `accent` 饱和度在选定区间（A：35–45%；B：≤35%） | 防止金色变土黄、蓝色变监控台 |
| 双主题令牌完整性 | `set(COLORS_LIGHT) == set(COLORS_DARK)`，且曲线 observation 两模式都有 | 防止暗色漏一个键 → 半亮半暗 |
| 颜色唯一来源 | 扩展现有扫描：除 `theme.py` 外不得出现 `#RRGGBB` 字面量 | 已接近达成，只差 `history_window.py:170` |
| 纠正框选中态不裁字 | §2.3 | 已验证缺陷回归 |

> 对比度测试要**纯标准库**（本项目零运行依赖是硬约束）。`contrast_report.py` 现在就是
> 零依赖实现，搬过去即可，不要为此引入 `colour-science` 之类。

## 6. 明确**暂不应处理**的问题

| 不做 | 为什么 |
|---|---|
| 改曲线算法/平滑 | 平滑只能改善表达，不能改模型输出或造虚假峰值——这是产品底线 |
| 重做信息架构 | 首屏三问（现在什么状态 / 最近发生什么 / 我能做什么）v5 已达成，本轮截图复核仍成立 |
| 引入 Qt 主题库 / 自动派生暗色 | 派生出来的暗色一定需要手工校准（本轮 §1.2 就是证据），库只会掩盖债 |
| 危险操作改红色 | 属于"是否引入第三色相"的产品决策，与本次色板探索正交，单独拍 |
| 图标系统重绘 | `IconButton` 描线风格与新骨架不冲突，换色即可 |
| 增加动效 | 现有 130/220/320ms + EASE_OUT 足够；"无意义动画"已被明确排除 |
| 卡片化 / 玻璃拟态 / 渐变 | 用户约束明确排除，且与"靠明度分层"的骨架冲突 |
| 6h/24h/7d 时间范围 | v5 已决定推迟，与视觉无关 |
| 模型精度宣称 | 7 天真实使用数据未回收前，README 里"精度未验证"的诚实表述不许改 |
