## 1. 符号级扫描（双口径）

用 AST 做两个保守检查（脚本放在仓库外，不自己变成新尾巴）：

| 检查 | 口径 | 结果 |
|---|---|---|
| 未使用 import | 绑定名在**本文件**里的出现次数 ≤ 1（仅定义处） | 37 个文件命中 |
| 只在定义处出现的方法 | 方法名在**全仓**出现次数 ≤ 1，排除 dunder / Qt 事件 / property / 静态方法 | 6 个命中 |
| 零引用顶层符号（函数/类/常量） | 全仓词频 ≤ 1 | 3 个（全是 `theme.py` 的小常量，保留） |

### 清掉的

- **37 个文件的未使用 import**，含 `main_app.py` 里 `QSizePolicy` / `app_font_num`、`windows/main_console.py` 里整整一段 `from emowave import (Observation, ObservationSource, ModelParameters, UserCorrection, CorrectionDimension, CorrectionSource, get_archetype, DEFAULT_ARCHETYPE_KEY)`——这 8 个符号在视图层重构后早已搬到 `presenters/`，import 忘了删；`correction_sheet.py` 里 7 个不再使用的 Qt 绘图类等。
- **3 个过时方法**：
  - `EmotionCurveWidget.point_at`（16 行）—— 注释写着"纠正上滑框拖点用"，但纠正框早已改用 `correction_canvas.py` 自己的命中测试，这是旧实现的残留；
  - `EmotionCurveWidget.value_to_y`（3 行）—— 只服务上面那个方法的对称工具；
  - `InputPanel.set_recording`（4 行）—— 注释自己写着"兼容旧接口"，而全仓无人调用。

### 故意保留的

`EmotionCurve.valence_at` / `arousal_at`、`Calibrator.residual_at` 各 2–3 行——它们是**内核对 pip 包消费者的语义接口**，删掉属于破坏性变更，收益（6 行）远小于代价。留。

> 净效果只有 **−40 行**。这不是失败：这一波的产出是"**没有悬空依赖**"，
> 而不是行数。行数账在前四波已经结清。

## 3. 新增护栏：代码体积预算（棘轮）

```python
LOC_BUDGET = 23000   # 21.9k 是瘦身后水位，留 ~5% 余量

def test_python_line_budget():
    ...
    assert total <= LOC_BUDGET, "要么删等价代码，要么上调 LOC_BUDGET 并说明理由"
```

理由：孤儿守卫只能拦"没人 import 的模块"，拦不住"每个模块都悄悄胖 30 行"。
预算是一道**总量棘轮**——要加功能，就先删等价代码；确实要涨，必须显式改常量并在 commit 里交代。

**自检**：把 `LOC_BUDGET` 临时压到 1000，护栏立刻红：

```
AssertionError: Python 代码 21892 行，超出预算 1000 行（+20892）
```
