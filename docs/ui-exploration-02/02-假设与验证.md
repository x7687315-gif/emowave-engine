## 2. 两套方案共同的底线（实测，不是声称）

### 2.1 灰度文字只有三级合法层级

| 令牌 | 值 | 对比度（对 paper #F5F5F5） | 用在哪 |
|---|---|---:|---|
| INK | #1A1A1A | **15.96:1** | 状态句、水位线、当前值 |
| INK_2 | #4D4D4D | **7.75:1** | 模型线、观察点、正文 |
| MUTED | #6E6E6E | **4.68:1** | 说明行、时间刻度、轴标签 |
| FAINT | #B0B0B0 | 1.99:1 | **只许画线**（基线点线、±1σ 包络、禁用态），禁止承载文字 |

> 这是本轮一个真实的自我修正：初版我把 `#B0B0B0` 用作 8px 时间刻度与页签文字，
> 实测只有 1.99:1，是明确的 AA 违规。灰阶并不能"多留几级淡字"——
> **三级文字灰已经是下限**，再淡就不合法。这条应写进正式重构的护栏测试。

### 2.2 曲线语义两套一致，画法不同

| 语义 | A | B |
|---|---|---|
| 观察点 | 实心圆 r=3.0 | 实心圆 r=2.8 |
| 模型估计 | 1.6px 实线 | 1.2px 实线 |
| 预测 | 1.6px 虚线 | 1.2px 虚线 |
| 修正 | 6px 空心方框 | 6px 空心方框 |
| 基线 | 1px 点线 + 就地标「常态 55」 | 1px 点线 + 轴上刻度「常态」 |
| 置信带 | 半透明填充 | 两条 ±1σ 点状包络 |
| 偏差面积 | 无 | 曲线与常态之间的浅灰填充 |

B 不用填充带，是因为它已经有一块"偏差面积"；两层半透明灰叠在一起会互相吞掉，
用户分不清"哪块是模型不确定、哪块是我偏离了常态"。

### 2.3 性能

全窗重绘（含 311 个曲线点）实测：**A 3.3 ms / B 4.1 ms 每帧**。
60fps 的预算是 16.7 ms，余量充足；两套都不需要额外缓存。

### 2.4 数据真实性

两套的曲线、读数、基线、纠正全部来自生产的 `ConsolePresenter`
（Matérn ν=3/2 状态空间 + 因果 Kalman + RTS 平滑），演示数据为
11 次自评 + 2 处拖点纠正。没有一条线是手绘示意。

## 3. 各自最值得验证的假设

每条都写成**可被证伪**的形式，并给出"若为假该怎么改"。

### A · 地平线

#### H-A1｜一句话足以承担首屏
> **假设**：把"平静 · 偏积极"放大到 31px、四读数压成一行 10px，
> 用户仍能准确说出"我现在怎么样、比平时高还是低"。

- **为什么重要**：这是 A 的全部赌注。若为假，A 的整个层级都要重排。
- **怎么验**：5 秒测试。给对方看 `a-idle.png` 5 秒，收起图，问：
  ①现在什么状态 ②比平时高还是低 ③大约几点最低。5 人里 ≥4 人三问全对 → 成立。
- **若为假**：把效价数字提升为"状态句的副标题"（24px），即回到半文字半数字。
  代价是 A 与现状的差别变小。

#### H-A2｜首屏不需要常驻滑块
> **假设**：把滑杆收进记录态，不会让用户找不到入口，也不会降低记录频率。

- **为什么重要**：这是省下 139px 的前提。若用户习惯"先调一下再说"，
  这个设计会打断一个高频动作。
- **怎么验**：让用户完成"记录一次当前感受"的任务，看是否需要提示才能开始；
  连续 3 天真实使用后对比记录次数是否下降。
- **若为假**：保留一条**极简滑杆**在空闲态（无数字、只有轨与柄），高度压到 48px。

#### H-A3｜无刻度的曲线仍能被读出信息
> **假设**：去掉 Y 轴刻度后，用户仍能说出"今天在午后掉下去、傍晚回来"这种走势。

- **为什么重要**：A 用"没有刻度"换"没有仪表感"，这是它气质的来源。
- **怎么验**：只看曲线区（遮住顶部文字），让用户复述走势；再问"最低点大概在几点"。
- **若为假**：加一条 0 / 50 / 100 的极淡刻度（MUTED，8.5px），不画轴线。

### B · 水位

#### H-B1｜横线被读成"现在"，而不是"阈值/目标"
> **假设**：横贯画面的那条 2px 实线 + 右侧数值 + 轴上的点，
> 足以让人理解"这是我此刻的位置"，而不会误读成"目标线 / 警戒线"。

- **为什么重要**：B 的整个隐喻建立在这条线上。误读会让方案失效。
- **怎么验**：5 秒测试后追问"那条横线是什么？"。≥4/5 答"现在的位置/当前状态" → 成立；
  若多人答"目标/上限"，则隐喻失败。
- **若为假**：把横线改为**不贯穿**的短标记（从轴伸出 16px）+ 末端小圆点，
  弱化"阈值"联想；或直接在轴端写「现在」。

#### H-B2｜偏差面积比数字更快传达"高于/低于常态"
> **假设**：曲线与常态之间的灰色面积，比"比你的常态高 5"这句话更快被理解。

- **为什么重要**：这是 B 相对 A 唯一新增的视觉元素，也是它"有信息密度"的来源。
- **怎么验**：A/B 交替展示（打乱顺序），问"今天大部分时间在常态之上还是之下"，
  记录反应时间与正确率。面积组更快且不更差 → 成立。
- **若为假**：去掉填充，只保留"比你的常态高 5"这一行文字 + 轴上的常态刻度。

#### H-B3｜拖动水位线比拖滑块更自然
> **假设**：记录时直接拖动水位线设定效价，比"找滑块→拖→看数字"更直觉。

- **为什么重要**：这是 B 在交互层的核心创新；也是它比 A 多做的一件事。
- **怎么验**：任务"把效价设为 30"，比较 B（拖线）与 A（拖滑杆）的完成时间与
  **落点误差**（±5 以内算对）。各 10 次。
- **若为假**（例如拖线精度差、误触多）：保留滑杆作为主输入，水位线只做展示。

#### H-B4｜反相控制带不会被误读为"错误/警告"
> **假设**：记录时整条控制带变黑，被理解为"正在记录"，而不是"出错了"。

- **为什么重要**：灰度下最强的手段就是明度反转，但它也最容易被读成告警。
- **怎么验**：展示 `b-recording.png`，问"现在应用在做什么？"；再问"这个黑条让你紧张吗？"
- **若为假**：改为"控制带保持浅色 + 左侧出现一条 4px 的竖线计数条"这类更弱的变化。

### 共同

| # | 假设 | 怎么验 | 若为假 |
|---|---|---|---|
| H-S1 | 纯灰度仍然"有设计感"，不显得单调 | 你直接看图判断（这是主观项，只有你能拍板） | 引入 exploration-01 的单一语义点缀色（金或蓝），结构不动 |

## 4. 需要你回答的问题

1. **选哪一套？**（也可以"选 A 的排版 + B 的偏差面积"这种组合，但要说清取舍）
2. 打开 EmoWave 时，你更想先看到"一句话"（A）还是"我在哪"（B）？
3. 输入控件"记录时才出现"能接受吗？（这是两套共用的决定，影响最大）
4. 模型页 / 历史页要不要一起重做？本轮只重塑了首屏；那两页目前仍是卡片堆叠。
5. 灰度之后，还想要一个语义点缀色吗？还是就保持纯灰度？

## 5. 本轮明确没做的事

- 深色模式（这一轮要先把**结构**定下来，颜色是下一层）
- 悬浮窗的重新设计（它现在仍是旧结构，等主窗定了再对齐）
- 模型页 / 历史页（截图里点页签会看到一行"沿用现有实现"的说明，这是有意为之）
- 空态 / 错误态的新版式
- 125% / 150% 缩放、真实中文字体回退的逐一核对
- 任何生产代码改动、任何提交
